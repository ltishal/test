# RPG ИИ-Мастер — обновлённая сборка

Русскоязычная браузерная RPG с потоковым ИИ-мастером, листом персонажа, XP, квестами, инвентарём, NPC, фракционными часами, озвучкой и локальными/серверными сохранениями. Интерфейс сохранён из оригинального проекта.

## Что улучшено

- **Защита промпта**: `/api/chat` принимает от браузера только сообщения `user` и `assistant`. Сервер всегда подставляет собственный `SYSTEM_PROMPT`, запрещает клиентские `system`, ограничивает запросы и длину ответа.
- **Защита бюджета**: SQLite с транзакционным резервированием хода; 40 бесплатных ходов на браузер, глобальный суточный предохранитель (по умолчанию 500 начатых ходов). Ошибочный/прерванный ход возвращает пользователю бесплатный или пакетный ход, но считается в глобальном защитном лимите. Параллельные ходы одного пользователя не допускаются.
- **Закрытое извлечение**: `/api/state` работает **только один раз** после успешно завершённого `/api/chat` с выданным этим запросом ticket. Ответ мастера сверяется по SHA-256 и привязан к серверной идентичности браузера и ID партии. Нельзя свободно гонять платные извлечения состояния.
- **Метрики**: учитываются отдельные вызовы мастера, извлечения и резюме; сведения об использовании токенов берутся у провайдера, где доступны. При отсутствии usage используются *приблизительные* значения (отмечаются в отчёте). Стоимость рассчитывается только при заданных ценах моделей.
- **Память**: инкрементальные резюме объединяются пачками ~10 сообщений, а не пересчитываются каждый ход; данные персонажа не дублируются в резюме. Резюме остаётся кэшем в памяти процесса, пересчитывается после перезапуска.
- **Состояние**: модель возвращает небольшой JSON-delta (`set/add/update/remove`), не полный лист. Изъятие предметов и снятие состояний происходит по явному `remove`.
- **XP**: сервер использует курсор `xp_scored_through`, не посылает сотни XP-хешей модели и избегает повторного начисления при обычном продолжении диалога. Старые сохранения мигрируют при следующем ходе. Известная граница: браузер по-прежнему присылает состояние персонажа, поэтому это не защищённая конкурентная игра с проверкой читов.
- **Сохранения**: принадлежность определяется подписанной HttpOnly-cookie. Клиентский `X-Client-Id` больше не даёт доступа к чужим файлам. Пользователь может экспортировать/импортировать партию текстом или JSON.
- **Администрирование**: `/api/diag` и `/api/admin/usage` требуют `ADMIN_TOKEN`, а без него отключены.

## Запуск локально

Нужен Python 3.10+.

```sh
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env  # Windows: copy .env.example .env
```

Заполните ключ API и настройки модели в `.env`. Если `APP_SECRET_KEY` не задан, он создастся в `saves/.app-secret`; **не удаляйте его**, иначе прежние cookies перестанут проверяться. Для Railway **задайте постоянный `APP_SECRET_KEY` через Variables**.

```sh
python app.py
```

Откройте `http://localhost:5000`. На Railway уже предусмотрены `Procfile` и `railway.json`. Установите `SAVES_DIR=/data`, подключите постоянный Volume к `/data`, настройте `OPENAI_*`, `EXTRACT_MODEL`, `SUMMARY_MODEL`, `APP_SECRET_KEY` и лимиты. **Оставьте один gunicorn-worker**, как в Procfile: память резюме и семафор ограничены процессом. SQLite может обрабатывать несколько процессов, но текущая версия рассчитана на один воркер.

## Тарифы: пока без настоящих платежей

Бесплатный лимит — `FREE_TURNS=40`. На вкладке **☰ → Лимит и доступ** игрок видит остаток и идентификатор учётной записи. **Оплата и платёжные провайдеры не подключены**; никаких фиктивных «купить» кнопок нет. Администратор с доступом к серверу может вручную назначить пакет или подписку:

```sh
python manage_access.py report
python manage_access.py grant 0123456789abcdef0123456789abcdef 300
python manage_access.py subscribe 0123456789abcdef0123456789abcdef 30
```

Где 32-символьная строка — **реальный ID**, скопированный пользователем из окна доступа, а не пример из команды. Подписка ограничена по умолчанию `SUBSCRIPTION_DAILY_TURNS=60` ходами/день по UTC; лимит пакета не имеет срока. Для тарификации нужна отдельная проверенная интеграция оплаты и серверные учётные записи.

### Метрики и диагностика

`ADMIN_TOKEN` — длинная случайная секретная строка. Не добавляйте её в JS, URL или публичный репозиторий. Запросы:

```sh
curl -H 'X-Admin-Token: YOUR_ADMIN_TOKEN' https://YOUR_DOMAIN/api/admin/usage
curl -H 'X-Admin-Token: YOUR_ADMIN_TOKEN' https://YOUR_DOMAIN/api/diag
```

`/api/admin/usage` показывает дневные агрегаты и число примерных измерений. `priced_cost_usd` **не обязательно весь расход**, если не заполнены все `*_PRICE_*`. Данные о цене модели берите у своего провайдера, не из устаревшей таблицы. Статус здоровья: `/api/health`.

## Обратная совместимость и ограничения

- Существующие сохранения в `localStorage` браузера должны продолжить открываться. Для надёжного переноса используйте **🔄 Перенос партии** → выгрузка JSON и импорт.
- Файлы прежнего сервера с видом `<старыйClientId>~<имя>.json` или `<имя>.json` не раскрываются новой анонимной cookie автоматически, поскольку старый ID не был защищён. Их можно восстановить вручную администратором, передав игроку JSON для импорта через интерфейс.
- **Гостевая cookie не является полноценной авторизацией.** Очистка cookies создаст новый профиль, может сбросить бесплатную пробу и лишить доступа к серверным сохранениям. Общий суточный лимит ограничивает общий расход, но при открытом публичном сайте возможны злоупотребления. Для коммерческого сервиса понадобятся реальные аккаунты, антибот-защита, платёжные webhook-и и резервные копии Volume.
- **Память:** резюме кэшируется в RAM, а вся история хранится в браузере и серверном сохранении. Если клиент потеряет историю и не сохранит партию, восстановить резюме само по себе нельзя.
- **Не тестировалось с живым LLM** в сборочной среде без ключа и зависимостей. Перед публикацией проведите серию 20–30 тестовых ходов и длинную сессию, проверив XP, удаление предметов, изменение квестов, цену и качество памяти. Начинайте с закрытой беты, а не с платежей.

## Проверки

```sh
python -m unittest discover -s tests -v
python -m py_compile app.py quota.py manage_access.py
```

Тесты не требуют реального API-ключа: они проверяют транзакции, токены, дельты и начисление XP.

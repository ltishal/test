# RPG ИИ-Мастер Ultimate — объединённая версия для Yandex AI Studio / OpenAI-compatible API / Railway

Текстовая ролевая игра на Flask: ИИ-рассказчик, лист персонажа, XP, NPC, квесты, броски кубиков, заметки, озвучка и сохранения. Основа — `RPG-master-yandex-railway.zip`.

## Быстрый запуск на Railway

1. Создайте сервис Railway из этого репозитория / архива и убедитесь, что используется команда запуска `gunicorn -c gunicorn.conf.py app:app`. Зависимости находятся в `requirements.txt`.
2. В **Variables** добавьте:

| Переменная | Значение |
| --- | --- |
| `YANDEX_API_KEY` | Ключ от Yandex AI Studio, хранить только в Variables |
| `YANDEX_FOLDER_ID` | Идентификатор каталога Yandex Cloud |
| `RPG_ACCESS_TOKEN` | **Обязательный** секретный ключ владельца с логином `owner` (или используйте `RPG_USERS_JSON`) |
| `RPG_SAVES_DIR` | `/data/saves` (при настроенном томе Railway; старое имя `SAVES_DIR` тоже поддерживается) |

3. Для долгой игры **создайте Volume** Railway с путём `/data` и задайте `RPG_SAVES_DIR=/data/saves`. Без тома и игровые сохранения, и **зарегистрированные аккаунты с паролями** хранятся лишь временно: при новом развёртывании или замене контейнера они могут исчезнуть. `RPG_SAVES_DIR` сам по себе том не создаёт.
4. Разверните сервис, откройте приложение: **владелец** входит по логину `owner` и значению `RPG_ACCESS_TOKEN` как паролю. **Друзья** выбирают «Зарегистрироваться», сами придумывают логин и пароль от 8 символов и затем входят через «Войти». Пароль не хранится в браузере: браузер получает отдельный сеансовый токен в `sessionStorage` вкладки.
5. `/api/health` возвращает статус приложения, провайдера и название модели (не секреты). После входа `/api/diag` показывает конфигурацию, а `/api/diag?ping=1` дополнительно проверяет реальный ответ модели.

Вместо Yandex можно использовать OpenAI или другой OpenAI-совместимый сервис: задайте `OPENAI_API_KEY`, при необходимости `OPENAI_BASE_URL`, и `OPENAI_MODEL`. Если одновременно заполнены настройки Yandex, они имеют приоритет.

Не добавляйте реальные ключи в GitHub, переменные исходников или файлы `.env` в репозитории. Для публичного сервера **не** устанавливайте `RPG_ALLOW_UNSAFE_LOCAL=1`.

## Значки персонажа вместо генерации портретов (v4)

- Раньше профиль запрашивал портрет на внешнем сервере генерации изображений и сохранял ссылку в браузере. **Эта функция и её сетевые запросы полностью убраны**. Никаких ключей, моделей изображений или отдельной оплаты не нужно.
- На стартовом экране появилась кнопка **«🧬 Создать персонажа»**, а в боковом меню — такой же пункт. Можно выбрать **расу, класс, предысторию и имя**, при необходимости использовать поле «Свой вариант» и добавить текстовое описание. Затем ИИ начнёт приключение с указанным героем.
- В карточке персонажа и полном листе отображаются три значка, например **🧝 Эльф · 🧙 Маг · ⛓️ Преступник**. Для человека — 🧑, воина — ⚔️, драконорождённого — 🐉 и т. д. Кнопка с большим значком в верхней части экрана открывает лист персонажа.
- При выборе готового мира сначала открывается конструктор героя. Кнопка **«🎲 Начать без анкеты»** позволяет играть как раньше, поручив выбор персонажа мастеру. Ввод персонажа свободным текстом тоже остался.
- Сами картинки не загружаются: эмодзи определяются локально по полям `race`, `class` и `background`, поэтому **старые сохранения автоматически покажут значки**. Структура сохранений и серверный API не изменились.
- Браузеры и ОС могут рисовать одни и те же эмодзи по-разному. Для нераспознанной расы/класса/предыстории используются нейтральные 🧬/🎯/📜.

Проверки UI: `node tests/test_character_icons.js` и `node tests/test_unicode_auth.js`, проверка сервера: `python -m unittest discover -s tests -v`.

## Отображение бросков и бонусов (v8)

Когда ИИ-мастер требует проверку, например **«Бросок Ловкости: 1d20 + 2 — Сложность 12»**, игрок нажимает обычную кнопку `🎲 d20`: сайт автоматически бросает **`1d20+2`**, показывает отдельную карточку с вычислением (например **`17 + 2 = 19`**) и затем отправляет мастеру конечный результат. Мастер не должен прибавлять модификатор повторно. Если мастер не указал число бонуса, но назвал характеристику, используется её модификатор из листа героя. Если мастер назвал ещё и бонус навыка, он складывается с бонусом характеристики.

Чтобы бросить **произвольный кубик**, воспользуйтесь ручным вводом `/roll 1d20+3` или «Свой бросок»: явный модификатор всегда приоритетен и не дополняется автоматически. Броски, не связанные с последней объявленной проверкой, остаются обычными. Вся информация о броске сохраняется в `ui_events`.

Проверка: `node tests/test_dice_check_bonus.js`. Для обновления V7 скопируйте `app.py` и `templates/index.html` из V8 в корень существующего репозитория с сохранением структуры.

## Модели и оптимизация

| Переменная | Значение |
| --- | --- |
| `YANDEX_MODEL` | Необязательно; по умолчанию `gpt://<folder-id>/deepseek-v4.1-flash` |
| `RPG_STATE_MODEL` | Необязательно; отдельная модель отслеживания состояния. По умолчанию модель рассказчика |
| `RPG_SUMMARY_MODEL` | Необязательно; модель сжатия истории. По умолчанию модель рассказчика |
| `RPG_MEMORY_UPDATE_AFTER` | Количество новых **старых** сообщений для обновления памяти; по умолчанию `16`, допустимое значение от `6` |
| `OPENAI_FREQ_PENALTY` | Штраф за повторения рассказчика; по умолчанию `0.35` |
| `OPENAI_PRES_PENALTY` | Штраф за повторения тем; по умолчанию `0.25` |

Архив памяти обновляется **не на каждом ходе**, а после накопления достаточного числа новых реплик. Сервер передаёт рассказчику системные инструкции, текущее состояние, резюме прошлых событий и непросуммированные последние реплики. При обновлении памяти отправляются только *ранее не обработанные* события вместе с текущим резюме. Память хранится в локальной сессии браузера и в JSON-сохранениях (`schema_version=4`).

Система характеристик делает отдельный запрос после ответа рассказчика. В нём теперь требуется **JSON только изменённых полей**, а не повтор всего состояния. Изменённый массив заменяется полностью; явно переданное `[]` удаляет предметы, заметки или квесты, если они исчезли из игры. XP, уровни и пороги опыта вычисляются сервером по явным наградам `+N XP`; модель не имеет права править их напрямую.

В логах Gunicorn видны длительность вызовов рассказчика, памяти и характеристик, число символов ответа и количество токенов для непотоковых запросов, если провайдер прислал сведения о расходе.

## Очередь ИИ и устойчивость API

- Одновременно выполняется не больше `LLM_MAX_CONCURRENT` обращений к модели (по умолчанию 2). Остальные запросы ждут до `LLM_QUEUE_TIMEOUT` секунд, после чего игрок получает понятную ошибку вместо зависшего запроса.
- Клиент API использует `LLM_TIMEOUT` и одну автоматическую повторную попытку сетевого запроса. Если провайдер не поддерживает `max_tokens`, `frequency_penalty` или `presence_penalty`, сервер повторяет запрос без неподдерживаемого параметра.
- Gunicorn запускается с одним worker-процессом и несколькими потоками: так лимит параллельных запросов не умножается на число workers. Число потоков можно задать через `WEB_THREADS`.
- Вспомогательные модели задаются через `RPG_STATE_MODEL` и `RPG_SUMMARY_MODEL`. Для совместимости также поддерживаются `EXTRACT_MODEL` и `SUMMARY_MODEL`.
- Ограничение размера одного HTTP-запроса — 4 МБ по умолчанию (`RPG_MAX_REQUEST_BYTES`).

## Перенос партии между устройствами

В боковом меню добавлена команда **«🔄 Перенос партии»** (также `/transfer`). Она экспортирует историю, состояние персонажа, архив памяти и карточки бросков/листа героя в один JSON. Его можно скопировать в буфер обмена или скачать файлом, а на другом устройстве — вставить или импортировать. Перед импортом текущая партия заменяется, поэтому сначала экспортируйте её или сохраните обычным способом. Войти на другом устройстве нужно в тот же аккаунт, чтобы продолжить пользоваться его серверными сохранениями.

При загрузке обычного серверного сохранения, если основной JSON повреждён, сервер пытается восстановить предыдущую версию из `.bak.json` и предупреждает об этом в чате.

## Самостоятельная регистрация игроков

В новой версии **не требуется создавать `RPG_USERS_JSON` для каждого друга**. Любой игрок открывает публичную ссылку Railway и выбирает **«Зарегистрироваться»**:

1. Придумывает уникальный логин: от 3 до 32 символов, буквы (включая кириллицу), цифры, `_` или `-`.
2. Вводит пароль длиной от 8 до 128 символов и повторяет его.
3. После регистрации сразу попадает в свой профиль. При следующем посещении входит через **«Войти»** с тем же логином и паролем.
4. Доступны только его сохранения — в каталоге `<RPG_SAVES_DIR>/<логин>/`. Герои, чат и память другого игрока не отображаются.

Логины регистронезависимы: `Ivan` и `ivan` — один аккаунт. Зарезервированы `owner`, `admin`, `root` и имена из `RPG_USERS_JSON`.

Пароли хранятся **не в открытом виде**, а как PBKDF2-HMAC-SHA256 с уникальной солью, в файле `<RPG_SAVES_DIR>/accounts.sqlite3`. После входа сервер выдаёт случайный сеансовый токен на 30 дней, в БД хранится только его SHA-256. Кнопка **«Сменить пользователя»** завершает текущий сеанс. Пароли нельзя восстановить из базы; функции сброса забытого пароля пока нет.

Для существующего владельца продолжает работать `owner` + `RPG_ACCESS_TOKEN`. Старые пользователи, заданные в `RPG_USERS_JSON`, тоже могут входить с указанным для них ключом как паролем; создание новых пользователей вручную больше не требуется.

### Настройки регистрации и лимиты для публичного сайта

| Переменная | Назначение |
| --- | --- |
| `RPG_REGISTRATION_ENABLED` | `1` (по умолчанию) — пользователи сами регистрируются; `0` — временно запретить новые регистрации |
| `RPG_REGISTRATION_CODE` | Необязательный общий **код приглашения** для регистрации. Если задан, показывается дополнительное поле для него |
| `RPG_AI_CALLS_PER_HOUR` | По умолчанию 180 вызовов ИИ за час на одного игрока; учитываются отдельно чат, обновления состояния и памяти |
| `RPG_AI_GLOBAL_CALLS_PER_HOUR` | По умолчанию 450 вызовов ИИ за час на весь проект |

Дополнительно ограничены регистрация (8 новых аккаунтов за час с одного IP) и попытки входа (12 за 15 минут для сочетания IP и логина). Все лимиты хранятся в SQLite и действуют между Gunicorn-процессами на одном диске. **Открытая регистрация означает, что любой посетитель может пользоваться вашим платным ИИ API** до достижения лимитов; если сайт доступен широкому кругу, рекомендуется задать `RPG_REGISTRATION_CODE` и выдавать его только друзьям. Лимиты уменьшают, но не устраняют риски расходов. Отдельной почты, восстановления пароля и CAPTCHA в этой версии нет.

Управление игровыми сохранениями: создать, загрузить, переименовать и удалить. Допустимы буквы (включая русские), цифры, `_` и `-`, пробел заменяется подчёркиванием. При перезаписи создаётся резервная копия `.bak.json`. Старые сохранения из корня `saves/` автоматически перемещаются в `owner/`, если сервис работает на том же диске. Файлы второй версии с префиксом устройства `clientId~name` переносятся с заменой `~` на `_`, чтобы их можно было открыть через новый API. **Перед обновлением сделайте резервную копию каталога `saves/`**.

## Локальный запуск

Нужен Python 3.10+. Установите зависимости:

```bash
python -m pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env` и заполните настройки провайдера и `RPG_ACCESS_TOKEN`. Файл `.env` загружается автоматически, если установлен `python-dotenv`; на Railway переменные задаются в разделе Variables. Если заданы `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`, используется Yandex AI Studio. Иначе можно использовать `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`. Для Ollama, например:

```bash
# В разных операционных системах синтаксис переменных окружения отличается.
export OPENAI_BASE_URL=http://127.0.0.1:11434/v1
export OPENAI_API_KEY=ollama
export OPENAI_MODEL=qwen2.5:7b
export RPG_ALLOW_UNSAFE_LOCAL=1
python app.py
```

Откройте `http://127.0.0.1:5000`. `RPG_ALLOW_UNSAFE_LOCAL=1` только для локальной разработки: встроенный сервер привязывается к `127.0.0.1`, а API в этом режиме отклоняет подключения не с loopback-адреса. В продакшене вместо него задавайте секретный ключ входа.

## Обратная совместимость и ограничения

- Старые сохранения `schema_version=2` и локальная сессия браузера `rpg_session_v9` загружаются; резюме накопится при следующем обновлении памяти.
- Сервер не отправляет полную прошлую историю после успешной архивации; память сохраняется даже после перезапуска страницы.
- Первое сжатие очень длинной старой кампании может быть дорогим. Последующие обновления инкрементальные.
- Это RPG-прототип, не строгий детерминированный движок D&D; правильность событий по-прежнему зависит от ИИ-модели. Без действующих API-ключей нельзя проверить реальное качество и стоимость генерации.
- Теперь есть регистрация с хешированием паролей, отдельными сеансами, SQLite и ограничениями частоты запросов. Для массового публичного проекта всё ещё понадобятся надёжное восстановление доступа, антибот-защита и мониторинг расходов API.

## Исправление v5: кириллические логины и ошибка fetch HTTP headers (23.11.2026)

Исправлена ошибка браузера `Failed to read the 'headers' property from 'RequestInit': String contains non ISO-8859-1 code point` при игре под кириллическим логином. Ранее клиент отправлял имя игрока в HTTP-заголовке `X-RPG-User`. Теперь все запросы используют **только** ASCII-безопасный `Authorization: Bearer <session-token>`, а сервер определяет пользователя по сессионному токену из SQLite. Кириллические логины поддерживаются; аккаунты, пароли, папки сохранений и игровые механики не менялись. Добавлен регрессионный тест `node tests/test_unicode_auth.js`.

**При обновлении на Railway без Volume будьте осторожны:** само исправление не удаляет файлы, но новое развёртывание может сбросить локальную базу аккаунтов и сохранения. Для надёжности рекомендуется подключить постоянный диск перед развёртыванием.

## Ритм повествования (v6)

ИИ-мастер теперь ориентируется на **4–6 коротких абзацев** за ход: непосредственный результат, конкретная деталь, реакция мира/NPC и новый поворот. По умолчанию генерация рассказчика ограничена примерно 700 выходными токенами (переменная `RPG_CHAT_MAX_TOKENS`; допустимый диапазон 256–1600). Настройки памяти и механики персонажа не изменились.

Если модель регулярно завершает фразы слишком рано, можно увеличить `RPG_CHAT_MAX_TOKENS` до `850`; если слишком многословна — уменьшить до `550`. Это верхний лимит токенов, а не строгий гарант числа абзацев: окончательная структура зависит от модели. Настраивать его необязательно. Обновление кода при использовании Railway Volume не должно удалять уже сохранённые аккаунты и игры, но резервные копии по-прежнему рекомендуются.

## V7: характеристики героя и броски в истории

- После создания персонажа мастер сначала генерирует первую сцену и обновляет игровые характеристики. Затем прямо в чате появляется карточка листа героя с шестью характеристиками, модификаторами, уровнем, HP и XP. Полный лист остаётся доступен по кнопке профиля.
- При нажатии `🎲 d20`, выборе пользовательского броска или команде `/roll 1d20+3` сначала появляется отдельная карточка результата (формула, кубики, сумма), затем идёт художественный ответ мастера из 4–6 абзацев.
- Карточки сохраняются в localStorage и в обычном файле игры (поле `ui_events`) и восстанавливаются в правильном порядке.
